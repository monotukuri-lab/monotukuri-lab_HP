コンテンツの編集手順

基本的な更新の流れ

  • * GitHubリポジトリを手元に取得して編集します
  • * ローカル環境で npm run dev を実行して表示を確認します
  • * 変更内容をコミットして main ブランチにプッシュします
  • * GitHub Actions が自動でビルドを行いサイトを更新します

新しいページを追加する場合

pages/ または events/ 配下にHTMLを作成し、vite.config.js の rollupOptions.input にパスを登録します。登録がないと本番ビルドに含まれません。

// vite.config.js の設定例
rollupOptions: {
  input: {
    main: resolve(__dirname, 'index.html'),
    // ...既存のページ
    newpage: resolve(__dirname, 'events/newevent2026.html'),
  }
}

イベント告知バナーの表示

index.html の中にあるバナー部分のコメントアウトを外して、リンク先や開催日時を編集します。終了時は再度コメントアウトして非表示に戻します。

<!-- index.html のイベント告知バナー部分 -->
<div class="max-w-xl mx-auto mt-8 sm:mt-12 mb-6 sm:mb-8">
  <a href="events/3dcontest2026.html"
    class="block bg-blue-600 hover:bg-blue-700 text-white text-center rounded-xl shadow-lg px-4 py-4">
    <div>イベント名</div>
    <div class="mt-2 text-yellow-300 font-bold">開催日時</div>
  </a>
</div>

公開とリリースの運用フロー

自動デプロイ（mainブランチへのプッシュ）

main ブランチにプッシュすると、GitHub Actions が自動で起動してビルドを行い、GitHub Pages へ即座に反映します。手動アップロードは不要です。

git add .
git commit -m "更新内容を記述"
git push origin main

自動リリース（バージョンタグによる配布物作成）

タグを付けてプッシュすると、GitHub Actions がビルド成果物を zip 形式に圧縮し、GitHubの Releases ページに自動で配布ファイルを作成します。

git tag v1.0.0
git push origin v1.0.0

ローカルでのビルド事前検証

プッシュ前に本番向けビルドの成否を確認したい場合は、以下のコマンドを実行してプレビューサーバーで動作を確認します。

npm run build
npm run preview

トラブルシューティング

GitHub Actions のビルドが失敗する場合

ワークフロー内では npm ci を実行します。package.json を変更した時は、必ず package-lock.json も一緒にコミットしてプッシュしてください。

追加したページが本番で 404 になる場合

vite.config.js の rollupOptions.input にパスが指定されているか確認してください。

開発サーバーが起動しない場合

Node.js のバージョンが 20 以上であることを確認してください。node_modules フォルダを削除して npm install を実行し直すと直る場合があります。
